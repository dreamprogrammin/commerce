# Scoped-стили и слои Tailwind

> Как чинится целый класс багов вёрстки на этом проекте и как продолжить работу.
> Состояние на 2026-08-10.

## Суть проблемы

**Scoped-стиль в SFC компилируется ВНЕ слоёв, а утилиты Tailwind живут в `@layer utilities`. Беслойное правило бьёт слой независимо от специфичности.**

Значит свой класс молча отменяет утилиту на том же элементе. Не «перебивает по специфичности», где помог бы `!important` или порядок, — а именно отменяет, потому что каскад сначала сравнивает слои и только потом всё остальное.

```vue
<button class="co-cta hidden lg:flex">
Оформить заказ
</button>

<style scoped>
.co-cta {
  display: inline-flex;
} /* ← побеждает всегда */
</style>
```

Здесь `hidden` и `lg:flex` не работают вовсе. Класс в разметке есть, эффекта нет, ошибок никаких.

### Что этим уже сломало

| Где                           | Класс задавал               | Умирало                    | Последствие                                              |
| ----------------------------- | --------------------------- | -------------------------- | -------------------------------------------------------- |
| `pages/checkout.vue`          | `.co-cta` → `display`       | `hidden`, `lg:flex`        | кнопка становилась строчной                              |
| `pages/checkout.vue`          | `.co-opt` → `gap`           | `gap-[11px]`               | вместо 11px рисовалось 13px                              |
| `pages/catalog/[...slug].vue` | `.cf-glass-btn` → `display` | `hidden`, `lg:inline-flex` | **кнопки фильтров для десктопа были видны на мобильном** |
| `pages/profile/children.vue`  | `.ch-btn-ghost` → `color`   | `text-destructive`         | кнопка «Удалить» не красная — починено 2026-08-08        |

## Лекарство

Обернуть содержимое `<style scoped>` в `@layer components`. Тогда каскад становится нормальным: утилита всегда перебивает класс, и раскладку можно править в разметке, не трогая стилевой блок.

> ### Но у лекарства есть обратная сторона — прочитать до того, как оборачивать
>
> Обёртка опускает стили файла ниже **любого беслойного CSS**, а не только поднимает над ними утилиты. Сторонние библиотеки свой CSS в слои не кладут — и после обёртки начинают выигрывать у наших классов.
>
> **Живой случай, 2026-08-10.** Пачку из 29 файлов обернули и откатили. Nuxt Icon отдаёт размеры иконок так:
>
> ```css
> :where(.i-lucide\:arrow-up-down) {
>   width: 1em;
>   height: 1em;
> } /* вне слоёв */
> ```
>
> Нулевая специфичность у `:where()` сделана намеренно — чтобы правило легко перебивали. Пока scoped-класс был тоже беслойным, специфичность решала в его пользу:
>
> ```css
> .cmh-icon[data-v-39678922] {
>   width: 19px;
>   height: 19px;
> } /* (0,2,0) — побеждало */
> ```
>
> После обёртки решает слой, и беслойное правило Nuxt Icon выиграло у слоя `components`. Иконки в мобильной шапке каталога поехали с **19px на 16px**. Ни сборка, ни линтер, ни тесты этого не заметили.
>
> Отсюда два вывода:
>
> 1. **«Конфликтов нет» от аудита — не гарантия.** Проверка статическая и видит только спор с утилитами Tailwind. Сторонний беслойный CSS она видит лишь частично (случай `<Icon>` теперь ловит).
> 2. **Сверка скриншотов до/после обязательна.** Именно она поймала регрессию, когда всё остальное молчало.

### Порядок слоёв — проверен, а не предположен

Это ключевой момент. Порядок слоёв определяется **первым появлением имени** в документе. Если бы чанк страницы грузился раньше `entry.css`, то `base` (preflight Tailwind) встал бы _после_ `components` и начал бы перебивать наши стили — кнопки потеряли бы фон.

Проверено на собранном приложении (`node .output/server/index.mjs`, запрос `/checkout`):

```
entry.<hash>.css      ← первым; объявляет properties → theme → base → components → utilities
Checkout.<hash>.css
…
checkout.<hash>.css   ← последним; попадает в уже готовый слот components
```

Слот `components` создан entry-файлом: **после `base`** (значит preflight эти стили не трогает) и **до `utilities`** (значит утилиты их перебивают). Ровно то, что нужно.

При сомнениях перепроверять так же — поднять сборку и посмотреть порядок `<link>` в отданном HTML.

## Инструменты

### `scripts/audit-scoped-style-layers.py`

Отвечает на вопрос «сломается ли что-нибудь, если обернуть этот файл». Ищет элементы, у которых есть и свой класс, и утилита, спорящие за одно свойство, — то есть всё, что **сейчас** полагается на победу scoped-правила.

```bash
python3 scripts/audit-scoped-style-layers.py pages/some.vue   # один файл
python3 scripts/audit-scoped-style-layers.py --all            # сводка по проекту
```

Код возврата 1, если найдены конфликты.

Учитывает `:class`-привязки и псевдосостояния (`:hover`, `:disabled`, `:focus`), различает `border-2` от `border-blue-200` и `text-sm` от `text-destructive`.

Отдельно помечает файлы, где свой класс задаёт размер `<Icon>`: после обёртки такой класс проиграет беслойному правилу Nuxt Icon (см. врезку выше).

**Чего не умеет.** Селекторы с потомками и псевдоэлементами (`.card h3`, `.x::-webkit-scrollbar`) с утилитами машинально не сверить — они выводятся отдельным списком под ручной просмотр. Такие файлы помечены «руками». И, главное, скрипт не знает про весь сторонний беслойный CSS — `<Icon>` это лишь один известный источник, могут быть другие. **Ноль конфликтов не означает, что вид не изменится.**

### `scripts/shot-pages.mjs` и `scripts/diff-shots.mjs`

Снимают семь состояний витрины на двух ширинах (390 и 1280) и сравнивают попиксельно. Корзина наполняется через интерфейс, поэтому корзина и оформление снимаются с товарами, а не пустыми.

```bash
node scripts/shot-pages.mjs before     # до правок, на поднятой сборке
# … обернуть, пересобрать, перезапустить сервер …
node scripts/shot-pages.mjs after
node scripts/diff-shots.mjs before after
```

Снимки ложатся в `node_modules/.cache/uhti-shots/` (в git не попадут); переопределяется через `SHOTS_DIR`.

**Сначала снять уровень шума.** Часть отличий — не регрессия: ленивые картинки и карусели дают 0.003–0.008% расхождения между двумя прогонами одной и той же сборки. Поэтому прогнать `after` дважды и сравнить `after` с `after2`: всё, что воспроизводится с точностью до пикселя и при этом отсутствует в контроле, — настоящее изменение.

Если Chromium не стартует из-за отсутствия `libnspr4`/`libnss3`/`libasound`, а `sudo` просит пароль: `apt-get download libnspr4 libnss3 libasound2t64` (root не нужен), `dpkg-deb -x` каждый пакет в свою папку и передать путь через `EXTRA_LIB_PATH=<папка>/usr/lib/x86_64-linux-gnu`.

### `scripts/wrap-scoped-styles-in-layer.py`

Механически оборачивает блок с отступом и поясняющим комментарием. Ничего не проверяет — сначала аудит.

```bash
python3 scripts/wrap-scoped-styles-in-layer.py pages/some.vue
```

**Правка 2026-08-08.** Проверка «файл уже обёрнут» искала подстроку `@layer` во всём теле блока и срабатывала на комментарии. Достаточно было упомянуть слой в пояснении — и файл молча пропускался с сообщением «уже в слое», хотя обёрнут не был. Отчёт при этом выглядел успешным, а страница оставалась со старым каскадом. Теперь комментарии вырезаются, а `@layer` ищется как at-правило в начале строки.

На момент правки под это подпадал `pages/catalog/[...slug].vue`: там в scoped-блоке есть комментарий про слои, оставшийся от починки `.cf-glass-btn`.

### Попытка обернуть пачкой, 2026-08-10 — откачена

29 файлов обернули разом, опираясь на «ноль конфликтов» от аудита. Сборка прошла, линтер остался на базовом уровне, 116 тестов зелёные. Сверка скриншотов показала три страницы с воспроизводимым отличием, и разбор одного из них вскрыл историю с Nuxt Icon из врезки выше. Пачку откатили целиком.

Вывод не «оборачивать нельзя», а «нельзя оборачивать вслепую». Идти малыми порциями, каждую сверяя скриншотами, и начинать с файлов, где `<Icon>` не стилизуется своими классами.

## Порядок работы

1. Ветку **до** первой правки: `git checkout -b refactor/...`
2. `python3 scripts/audit-scoped-style-layers.py <файл>` — конфликтов быть не должно.
3. Если файл помечен «руками» — глазами просмотреть вложенные селекторы из списка: не спорят ли они с утилитами на тех же потомках.
4. Снять эталон: поднять сборку и `node scripts/shot-pages.mjs before`.
5. `python3 scripts/wrap-scoped-styles-in-layer.py <файл>`
6. `corepack pnpm build` — должен пройти.
7. Перезапустить сервер, `node scripts/shot-pages.mjs after`, затем `node scripts/diff-shots.mjs before after`. Отличия разбирать до причины, а не списывать на шум — уровень шума мерить контрольным прогоном `after` дважды.
8. `corepack pnpm lint` — сверить с базовым уровнем, а не смотреть на абсолютное число: в репозитории есть предсуществующие падения (на 2026-08-07, сразу после этого коммита — 872 problems / 854 errors / 18 warnings). Правленый файл в выводе фигурировать не должен. Число меняется от коммита к коммиту — снимать базовый уровень на `dev` **до** своих правок, а не брать отсюда.
9. `corepack pnpm test:run`
10. Мердж `--no-ff` в `dev`, пуш, ветку удалить.

Prettier на части файлов ругается **и без наших правок** — расхождение Prettier с ESLint предсуществующее, `--write` не запускать, он подерётся с линтером.

## Чего проверка не заменяет

Сборка, линтер и тесты про вёрстку не знают вообще. 29 обёрнутых файлов прошли всё это зелёными, имея внутри съехавшие иконки. Единственное, что поймало регрессию, — сверка скриншотов.

Но и она не всесильна: снимаются семь состояний витрины, а `/profile/**` закрыт Google OAuth и агенту недоступен — эти страницы отдавать на проверку человеку. Остальное (админка, бренды, страница успешного заказа) в текущий набор снимков не входит, так что файлы, влияющие только на них, визуально не покрыты — либо расширять набор, либо смотреть руками.
