# Scoped-стили и слои Tailwind

> Как чинится целый класс багов вёрстки на этом проекте и как продолжить работу.
> Состояние на 2026-08-08.

## Суть проблемы

**Scoped-стиль в SFC компилируется ВНЕ слоёв, а утилиты Tailwind живут в `@layer utilities`. Беслойное правило бьёт слой независимо от специфичности.**

Значит свой класс молча отменяет утилиту на том же элементе. Не «перебивает по специфичности», где помог бы `!important` или порядок, — а именно отменяет, потому что каскад сначала сравнивает слои и только потом всё остальное.

```vue
<button class="co-cta hidden lg:flex">
Оформить заказ
</button>

<style scoped>
.co-cta {
  display: inline-flex;
} /* ← побеждает всегда */
</style>
```

Здесь `hidden` и `lg:flex` не работают вовсе. Класс в разметке есть, эффекта нет, ошибок никаких.

### Что этим уже сломало

| Где                           | Класс задавал               | Умирало                    | Последствие                                              |
| ----------------------------- | --------------------------- | -------------------------- | -------------------------------------------------------- |
| `pages/checkout.vue`          | `.co-cta` → `display`       | `hidden`, `lg:flex`        | кнопка становилась строчной                              |
| `pages/checkout.vue`          | `.co-opt` → `gap`           | `gap-[11px]`               | вместо 11px рисовалось 13px                              |
| `pages/catalog/[...slug].vue` | `.cf-glass-btn` → `display` | `hidden`, `lg:inline-flex` | **кнопки фильтров для десктопа были видны на мобильном** |
| `pages/profile/children.vue`  | `.ch-btn-ghost` → `color`   | `text-destructive`         | кнопка «Удалить» не красная — починено 2026-08-08        |

## Лекарство

Обернуть содержимое `<style scoped>` в `@layer components`. Тогда каскад становится нормальным: утилита всегда перебивает класс, и раскладку можно править в разметке, не трогая стилевой блок.

### Порядок слоёв — проверен, а не предположен

Это ключевой момент. Порядок слоёв определяется **первым появлением имени** в документе. Если бы чанк страницы грузился раньше `entry.css`, то `base` (preflight Tailwind) встал бы _после_ `components` и начал бы перебивать наши стили — кнопки потеряли бы фон.

Проверено на собранном приложении (`node .output/server/index.mjs`, запрос `/checkout`):

```
entry.<hash>.css      ← первым; объявляет properties → theme → base → components → utilities
Checkout.<hash>.css
…
checkout.<hash>.css   ← последним; попадает в уже готовый слот components
```

Слот `components` создан entry-файлом: **после `base`** (значит preflight эти стили не трогает) и **до `utilities`** (значит утилиты их перебивают). Ровно то, что нужно.

При сомнениях перепроверять так же — поднять сборку и посмотреть порядок `<link>` в отданном HTML.

## Инструменты

### `scripts/audit-scoped-style-layers.py`

Отвечает на вопрос «сломается ли что-нибудь, если обернуть этот файл». Ищет элементы, у которых есть и свой класс, и утилита, спорящие за одно свойство, — то есть всё, что **сейчас** полагается на победу scoped-правила.

```bash
python3 scripts/audit-scoped-style-layers.py pages/some.vue   # один файл
python3 scripts/audit-scoped-style-layers.py --all            # сводка по проекту
```

Код возврата 1, если найдены конфликты.

Учитывает `:class`-привязки и псевдосостояния (`:hover`, `:disabled`, `:focus`), различает `border-2` от `border-blue-200` и `text-sm` от `text-destructive`.

**Чего не умеет.** Селекторы с потомками и псевдоэлементами (`.card h3`, `.x::-webkit-scrollbar`) с утилитами машинально не сверить — они выводятся отдельным списком под ручной просмотр. Такие файлы помечены «руками».

### `scripts/wrap-scoped-styles-in-layer.py`

Механически оборачивает блок с отступом и поясняющим комментарием. Ничего не проверяет — сначала аудит.

```bash
python3 scripts/wrap-scoped-styles-in-layer.py pages/some.vue
```

**Правка 2026-08-08.** Проверка «файл уже обёрнут» искала подстроку `@layer` во всём теле блока и срабатывала на комментарии. Достаточно было упомянуть слой в пояснении — и файл молча пропускался с сообщением «уже в слое», хотя обёрнут не был. Отчёт при этом выглядел успешным, а страница оставалась со старым каскадом. Теперь комментарии вырезаются, а `@layer` ищется как at-правило в начале строки.

На момент правки под это подпадал `pages/catalog/[...slug].vue`: там в scoped-блоке есть комментарий про слои, оставшийся от починки `.cf-glass-btn`.

### Первое, что стоит сделать

Конфликтов не осталось — можно брать пачками из «чисто» и оборачивать по порядку из следующего раздела.

`pages/catalog/[...slug].vue` стоит взять первым: аудит по нему чистый, а сам файл уже отметился в таблице поломок выше.

## Порядок работы

1. Ветку **до** первой правки: `git checkout -b refactor/...`
2. `python3 scripts/audit-scoped-style-layers.py <файл>` — конфликтов быть не должно.
3. Если файл помечен «руками» — глазами просмотреть вложенные селекторы из списка: не спорят ли они с утилитами на тех же потомках.
4. `python3 scripts/wrap-scoped-styles-in-layer.py <файл>`
5. `corepack pnpm build` — должен пройти.
6. `corepack pnpm lint` — сверить с базовым уровнем, а не смотреть на абсолютное число: в репозитории есть предсуществующие падения (на 2026-08-07, сразу после этого коммита — 872 problems / 854 errors / 18 warnings). Правленый файл в выводе фигурировать не должен. Число меняется от коммита к коммиту — снимать базовый уровень на `dev` **до** своих правок, а не брать отсюда.
7. `corepack pnpm test:run`
8. Мердж `--no-ff` в `dev`, пуш, ветку удалить.

Prettier на части файлов ругается **и без наших правок** — расхождение Prettier с ESLint предсуществующее, `--write` не запускать, он подерётся с линтером.

## Чего проверка не заменяет

Всё выше держится на сборке, тестах, чтении собранного CSS и порядке `<link>`. Утверждение «вид не изменился» опирается на отсутствие конфликтов, а не на просмотр страницы, — и этого мало: аудит сверяет свойства, а не то, как оно выглядит вместе.

Смотреть глазами при этом можно и нужно: Playwright в `node_modules`, скриншоты снимаются на любой ширине (`CLAUDE.md`, пункт 15 — там же про то, что скрипт должен лежать в корне репозитория). Закрыты только страницы за логином — `pages/profile/*` придётся отдавать на проверку человеку. После обёртки пачки файлов пройтись по мобильным раскладкам обязательно.
